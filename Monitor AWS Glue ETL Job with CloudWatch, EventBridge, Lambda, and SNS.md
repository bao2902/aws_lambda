# Concepts

## AWS Glue

AWS Glue is Amazon Web Services' serverless, fully managed data integration and ETL (Extract, Transform, Load) service.
* It allows data teams to prepare, transform, and move datasets between various storage systems (such as legacy SQL Server databases, S3 data lakes, and Snowflake data warehouses) without provisioning or managing underlying cluster infrastructure.

## AWS EventBridge

AWS EventBridge is a serverless event bus service that routes messages and state changes between AWS services, SaaS applications, and custom microservices.
* In your enterprise architecture, AWS EventBridge acts as the central traffic controller that intercepts AWS Glue pipeline execution state changes from CloudWatch Logs and automatically routes them to AWS Lambda for error handling and alerting.

## EventBridge Bus

EventBridge Bus (or Event Bus) is a pipeline-like channel inside AWS EventBridge that receives incoming events from various sources and routes them to downstream targets based on matching rules.
* Think of an Event Bus as a central router or message switchboard: events arrive at the bus, the bus evaluates them against all defined rules, and any matching events are pushed to designated targets (such as AWS Lambda, SNS, or SQS).

## EventBridge Rule

EventBridge Rule is the core logic unit within AWS EventBridge that connects an Event Bus to specific Targets.
* If the Event Bus is the switchboard routing traffic, the Rule is the actual conditional instruction that says: "When an incoming event matches this pattern, transform the data and forward it to these specific destinations."

## EventBridge Pattern

EventBridge Pattern (or Event Pattern) is a JSON structure used within an AWS EventBridge Rule to filter incoming events on an event bus.
* Instead of triggering downstream resources (like AWS Lambda or SNS) for every single event passing through the system, an EventBridge pattern acts as a precise declarative filter. EventBridge only routes an event to its designated targets if the structure and values of the incoming event match the pattern.

## AWS Lambda

AWS Lambda is Amazon Web Services' flagship serverless event-driven compute service. It allows developers to run code in response to events without provisioning, managing, or scaling underlying virtual machines or servers.

## Lambda Event Function

Lambda Event Function (often referred to simply as an event-driven Lambda function) is an AWS Lambda function designed specifically to react to incoming JSON event payloads generated by upstream AWS services, custom applications, or third-party webhooks.
* In event-driven architectures, the Lambda function does not poll continuously for work or run constantly. Instead, an Event Source triggers the execution, passing a structured data payload into the function's handler method.

## Lambda Handler

Lambda Handler is the specific method or function in your code that AWS Lambda invokes when the function executes. It serves as the primary entry point for execution, similar to main() in traditional programming languages.

## AWS SNS

AWS SNS (Simple Notification Service) is a fully managed, publish/subscribe (Pub/Sub) messaging service built for high-throughput, microservice-to-microservice communication and instant end-user notifications.

## SNS Topic

SNS Topic is a logical access point, communication channel, and message broker within AWS Simple Notification Service (SNS).
* It acts as a central intermediary that decouples message senders (Publishers) from message receivers (Subscribers).

## SNS Subscription

SNS Subscription is the exact connection binding an AWS SNS Topic to a specific destination endpoint. While the Topic acts as the channel publishing events, the Subscription defines who gets the message, how it gets delivered (the protocol), and what conditions must be met.

## AWS CloudWatch

AWS CloudWatch is Amazon Web Services' primary monitoring, logging, and observability service designed for DevOps engineers, developers, and data architects.
* It collects operational data—including logs, metrics, and event records—across your entire AWS infrastructure and application ecosystem to give you a single unified view of system health and performance.

## CloudWatch Log Group

CloudWatch Log Group is a organizational container inside Amazon CloudWatch Logs that collects, manages, and stores related Log Streams that share identical configuration settings.
* Think of a Log Group as a top-level folder dedicated to a specific application, microservice, or infrastructure component (e.g., all execution logs for a single AWS Lambda function or AWS Glue job).

## AWS IAM

AWS IAM (Identity and Access Management) is the central security service in Amazon Web Services that securely controls who can be authenticated (signed in) and authorized (has permissions) to access AWS resources.
* IAM acts as the front gate and security guard for your entire AWS cloud environment. Every single API request made to AWS—whether by a human user clicking in the AWS Management Console, a Python script executing on an EC2 instance, or an AWS Lambda function running code—is evaluated and governed by IAM.

## IAM Role

IAM Role is an AWS identity designed for temporary access to resources, carrying specific permission policies without requiring permanent credentials (like passwords or static long-lived access keys).
* Instead of assigning static credentials directly to a user or hardcoding access keys in application code, a human user, application, or AWS service assumes an IAM role dynamically to receive short-lived, automatically rotatable security tokens.

## IAM Policy

IAM Policy is a JSON document that explicitly defines permissions—specifying what Actions are allowed or denied on which Resources, under specific Conditions.
* While an IAM Role or IAM User represents who is making a request, the IAM Policy is the actual rulebook that tells AWS whether to grant or block that request.

**Create event function**

* Function ARN: arn:aws:lambda:us-east-1:481742614791:function:dev-glue-alerts
* Description: Processes Glue job failure events and fans out alerts to SNS/Slack

Lambda > Event Functions > dev-glue-alerts > Code > Runtime settings

* Runtime: Python 3.13
* Handler: lambda_function.lambda_handler
* Architecture: arm64

**Create Lambda handler**

Lambda > Event Functions > dev-glue-alerts > Code > lambda_function.py

> def lambda_handler(event: dict, context) -> dict:
>   logger.info("Event received: %s", json.dumps(event))

>   detail     = event.get("detail", {})
>   job_name   = detail.get("jobName",  "unknown-job")
>   run_id     = detail.get("jobRunId", "unknown-run-id")
>   state      = detail.get("state",    "UNKNOWN")

>   run_details = _get_job_run_details(job_name, run_id)
>   error_msg   = run_details["error_msg"]
>   started_on  = run_details["started_on"]

>   try:
>     secret_resp = sm_client.get_secret_value(SecretId=ALERTS_SECRET_ARN)
>     webhook_url = json.loads(secret_resp["SecretString"])["SLACK_WEBHOOK"]
>     slack_payload = slack_blocks.generate_glue_alert_blocks(
>       job_name, run_id, state, started_on, error_msg,
>       cw_url   = _cw_logs_url(REGION, job_name, run_id),
>       glue_url = _glue_run_url(REGION, job_name, run_id),
>     )
>     _post_to_slack(webhook_url, slack_payload)
>   except Exception as exc:
>     logger.error("Slack channel delivery failed: %s", exc)

>   _publish_sns(job_name, run_id, state, started_on, error_msg)

>   return {"statusCode": 200, "body": "Notifications dispatched"}
